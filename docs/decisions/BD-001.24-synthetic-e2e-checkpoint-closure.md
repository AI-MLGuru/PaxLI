# BD-001.24 — Synthetic/Local E2E Biometric Checkpoint: Closure

**Status:** CLOSED. Both runs of the frozen scenario matrix executed
against real infrastructure (real browser, real API, real Postgres,
real MinIO, real InsightFace/PaddleOCR) and produced a real, understood
result. The checkpoint closes with that result standing as the record —
it is not held open pending [REL-004](REL-004-reference-reverification-tight-crop.md),
and the frozen fixture mapping is not further substituted to force a
different outcome.

## 1. What this checkpoint was for

To stand up the real PaxLI stack (not mocks, not unit tests) and drive a
small, frozen scenario matrix through it end to end, establishing what
the current system actually does under real infrastructure — including
whatever real defects that surfaces. It was never a demand that the
system reach `VERIFIED`; a defensible `INCONCLUSIVE`, reached for an
understood reason, is a legitimate and useful checkpoint result.

## 2. Frozen scenario matrix

- **Run 1 — same-identity:** `subject_a` reference/document image vs.
  `subject_a/Image_7.jpg` (probe/selfie), same person.
- **Run 2 — different-identity:** the same reference/document image vs.
  `subject_b/Image_6.jpg` (probe/selfie), a different person.

**Fixture substitution history (unchanged by this closure, recorded
here for one complete reference):** the reference/document image was
originally `subject_a/Image_4.jpg`, revised to `Image_9.jpg` (exceeded
the 10 MB evidence size limit), revised to `Image_6.jpg` (genuine
`NO_FACE_FOUND` on an AI-generated substitute), and finally revised to
`Image_1.jpg` because of REL-001's documented native PaddleOCR crash
cluster. Each revision is a recorded fixture substitution caused by a
documented infrastructure defect, per REL-001 §4 — never silent
continuation under the original mapping. `Image_1.jpg` was independently
checked, before use, for exactly one detectable face, suitable detection
confidence, and clean OCR behavior (`tests/fixtures/biometric/_diagnostics/image_diagnostics.md`).
No further substitution follows from this closure.

## 3. Results

**Run 1 — INCONCLUSIVE.** Session `f7a47691-af40-40bb-94e2-707c79a2db93`
(the instrumented retry under REL-003; two earlier attempts, sessions
`dcf00a1b-...` and `62edf65e-...`, reached the identical result before
REL-003's instrumentation was added). The frozen `Image_1.jpg` →
`Image_7.jpg` mapping was executed against the real stack. Reference
extraction successfully detected the face in the original document
image (confirmed directly: `face_count=1`, `det_score=0.8659`,
identical across three real-server attempts and every isolated repro).
Downstream reference re-verification then failed deterministically on
the extractor-generated tight crop (`FACE_DETECTION_REFERENCE =
INCONCLUSIVE / DETECTION_NO_FACE`). No `FACE_MATCH` evidence was ever
produced — the pipeline correctly did not fabricate a comparison from
insufficient reference evidence. No final verification decision beyond
session-level `INCONCLUSIVE` was produced. This is a real, identified
implementation/integration limitation, tracked under REL-004, not a
fixture, upload, storage, or concurrency problem (REL-001/REL-002/REL-003
each ruled out their respective hypothesis with direct evidence).

**Run 2 — INCONCLUSIVE.** Session `87067ca3-f711-4f3a-bdf6-fd8156c6956b`.
The same reference/document image against `subject_b/Image_6.jpg`
(different person). Recorded independently of Run 1, per its own
evidence: `FACE_DETECTION_PROBE=PASS`, `FACE_QUALITY_PROBE=PASS`
(`score=0.72415588805017`), `FACE_DETECTION_REFERENCE=INCONCLUSIVE /
DETECTION_NO_FACE`, no `FACE_MATCH` produced. Run 2 hits the identical
REL-004 mechanism at the identical stage, for the identical reason —
this is expected, not a coincidence requiring separate explanation,
since both runs share the same reference/document image. Run 2's result
is reported as its own fact, not merged with or excused by Run 1's.

## 4. The architectural point this checkpoint actually established

`INCONCLUSIVE` here is the system behaving correctly, not a failure to
reach a verdict that should have been reachable. The pipeline is not
saying "we could not re-detect the crop, therefore this person is not
verified" — that would be fabricating `REJECTED` from a technical
failure, which the constitution forbids outright. It is saying "the
evidence required to make a verification decision is insufficient,"
which is exactly `INCONCLUSIVE`'s intended role. Both runs demonstrate
this distinction holding under real infrastructure, under a real,
previously-undiscovered defect, without any component overstepping into
declaring a verdict it was not entitled to make.
