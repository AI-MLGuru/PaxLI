## 3. Implemented scope

### 3.1 Workflow boundary

`VerificationWorkflowService` now receives a required biometric processor and
invokes it in the `PROCESSING` branch after document processing and before
Decision Engine evaluation.

The ordering is:

```text
DocumentProcessor
      -> BiometricProcessor
      -> DecisionOrchestrator
      -> persisted decision
```

Biometric exceptions are not swallowed or translated by the workflow.

### 3.2 Composition root

The API composition root now constructs the complete biometric dependency
graph, including the shared InsightFace detection model, the embedder model,
reference resolver, face capabilities, matcher, and `BiometricProcessor`.

The existing lazy model construction pattern is preserved so failed model
construction does not poison the singleton state and a later request can
retry.

### 3.3 Construction-site compatibility

All direct workflow construction sites affected by the new required
constructor dependency were updated. Unit tests use a protocol-shaped fake;
integration tests use the existing no-op-safe biometric path where biometric
evidence is outside their scope.

### 3.4 Mandatory lifecycle gate

The integration suite proves the required real lifecycle:

```text
/submit
  -> DocumentProcessor
  -> BiometricProcessor
  -> FACE_MATCH
  -> DecisionOrchestrator
  -> persisted VERIFIED decision
```

The test also verifies persisted effective `FACE_MATCH` state, rather than
only trusting the in-memory workflow return value.

## 5. Findings and triage

**No implementation defects remain open for Slice I.**

The principal validation issue was an invalid SELFIE test fixture. Media
validation correctly rejected the bytes before biometric processing. Replacing
the fixture with valid JPEG content restored the intended workflow reachability
and did not require an architecture change.

The required biometric protocol boundary and constructor dependency caused
expected direct-construction fallout in older integration tests. Those call
sites were updated to satisfy the frozen contract.

## 6. Security and data-protection confirmation

Slice I does not grant final-decision authority to the biometric processor.
Biometric components produce evidence; `DecisionOrchestrator` and the Decision
Engine remain the only final-outcome authority.

The workflow does not treat processing completion as verification success, and
technical or dependency failure is not converted into a fabricated rejection
or verification outcome.

The existing tenant-scoped persistence and audit paths remain in force. No
credentials, biometric payloads, or raw document data were added to ordinary
audit output by this slice.

## 7. Explicitly deferred scope

- queue or durable workflow infrastructure;
- changes to Decision Engine policy semantics;
- changes to final verification outcome ownership;
- a new API surface beyond the existing verification workflow;
- any unrelated workspace modifications or decision-document consolidation.

## 8. Final closure statement

Slice I is **CLOSED**. The existing biometric subsystem is now reachable
