## 3. Implemented scope

### 3.1 Real lifecycle, replacing the earlier simulated flow

Session creation, document/selfie/liveness evidence upload (file and native
camera capture), a single `submit()` call, and bounded polling against
`GET /{session_id}` all now drive the real `PaxliApiClient` against a
configured API base URL. The browser never computes `VERIFIED`/`REJECTED`/
`REVIEW_REQUIRED`/`INCONCLUSIVE` itself — only the server's own terminal
projection is displayed.

### 3.2 Two real defects found and fixed during hostile browser validation

Both were invisible to the existing Node/jsdom-based unit tests and would
have affected real users, not just this validation pass:

1. `PaxliApiClient` stored the bare `fetch` reference and called it as
   `this.fetcher(...)` — a de-bound call that throws `Illegal invocation`
   in every real browser, since native `fetch` requires `window` (or a
   Window-derived object) as its receiver. Fixed by binding the default
   fetcher to `globalThis` at construction.
2. The submit button's "submit exactly once" guarantee relied solely on the
   HTML `disabled` attribute, which only takes effect after React
   re-renders. A genuine same-tick double-click — reproduced with two
   native `click()` calls dispatched synchronously, not a contrived
   browser-API bypass — sent two real `POST /submit` requests. Fixed with
   a synchronous `useRef`-backed in-flight guard checked before any
   `await`, independent of render timing.

### 3.3 Camera lifecycle

`MediaStreamTrack.stop()` is called on capture, cancel, permission denial,
and component unmount — verified directly via a `MediaStreamTrack.prototype.stop`
instrumentation counter in the Playwright suite, not inferred from the
absence of a visible leak.

### 3.4 Visual and copy redesign

Retired the teal accent that had been used throughout despite not being
part of the requested silver-blue / gold-orange / copper palette; rebuilt
the token system around three deliberate roles (silver-blue structural,
gold/copper spent sparingly for the primary action and decision moment,
copper alone for section index numerals). Added a "PaxLI by PaxAlpha"
wordmark lockup sized to the logo asset's real 1024×572 aspect (no
cropping). Removed the sweeping scan-line animation, slowed the flow-line
pulse and identity-ring orbit, added a tablet breakpoint, fixed the demo
page's missing mobile grid-stacking rule, tightened three headline lines,
and deleted a block of dead CSS left over from an earlier, already-removed
eight-card layout.

## 5. What this closure does not claim

**Real-backend browser validation was not performed.** Every hostile-matrix
result in §4 is against a Playwright-intercepted mock API, not a running
PaxLI backend. No test in this record proves the dashboard correctly drives
the actual verification pipeline described in `BD-001.21` (Slice M) — only
that the dashboard correctly drives the `PaxliApiClient` contract as
specified. Standing up a local PaxLI backend (FastAPI + Postgres + MinIO)
to run this dashboard against it end to end remains unattempted and is not
implied by anything in this record.

This distinction matters specifically because of §3.2: both defects found
this session were invisible to unit tests and were only caught by driving
a real browser against *something* — but that something was a mock, not
the real API. A defect specific to the real backend's actual response
shapes, timing, or error behavior would not have been caught by this
validation pass and is not ruled out by it.
